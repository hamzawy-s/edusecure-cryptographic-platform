# Key management plan

| Key | Generation and use | Location in local demo | Custody / rotation |
|---|---|---|---|
| Root CA ECDSA P-256 | Signs local HTTPS and issuer certificates | `keys/root-ca-key.pem`; public certificate in `certificates/root-ca.pem` | Generated by `scripts/init_keys.py`; not loaded by web process after bootstrap. Keep offline and rotate only with planned trust migration. Local filesystem is not a secure offline vault. |
| Issuer ECDSA P-256 | Signs canonical credential documents | `keys/issuer-key.pem`, distinct from Root CA key | Loaded by service for issuance; demo only. Production: HSM/KMS, key identifiers, overlap period, revocation and audit. |
| Server ECDSA P-256 | TLS server authentication | `keys/server-key.pem` | Local service key; certificate in `certificates/server.pem`. Rotate before expiration and reissue under trusted CA. |
| File/grade RSA-3072 | OAEP/SHA-256 wrapping/unwrapping of per-record DEKs | `keys/file-wrap-rsa3072.pem` | Separate from signatures and DB. Production: HSM/KMS, versioned keys, background rewrap and recovery testing. |
| Per-object AES-256 DEK | Encrypts one file or grade with GCM | In memory during use; stored only RSA-wrapped | New random key and nonce per object; destroy on process completion. |
| Session HMAC secret | Signs expiring session payload | Environment variable; randomized ephemeral fallback for local development | Configure stable high-entropy value for a deployment; rotate by invalidating sessions and replacing secret. Never commit. |
| Webhook HMAC secret | Signs/verifies simulator events | Independent environment variable; randomized ephemeral fallback | Rotate separately from session secret. A production gateway uses provider-managed signing secrets and key IDs. |

All generated keys/certificates are ignored by Git and omitted from source ZIP. `.env.example` contains placeholders only. Database rows store password salts/digests, GCM nonces, ciphertext, digests, and wrapped DEKs; private keys and plaintext DEKs are not stored in SQLite. Local backup files need encryption and restricted access. Root-CA recovery and revocation are manual and are not represented as completed production controls.
